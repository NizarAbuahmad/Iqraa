## Brand — two generations

**Reels 2, 5 and 10–12 use the current Iqrra identity; Reels 1, 3, 4 and 6–9 still use the old one** and want the same
re-skin (their takes are committed, so it is a rebuild, not a re-record — except Reel 1).

- *Old (Reels 1, 3, 4, 6–9):* the raster `assets/logo-wordmark.png` (from `attached_assets/0_ikraa_logo…png`: a glowing
  «إقرأ / IQRA» on navy `#081B3A`) on every end card, navy ground, aqua `#34D6C6` highlights.
- *New (Reels 2, 5):* the app's own vector lockup — leaf tile + «اقرأ» wordmark — generated by `make_brand.mjs` straight
  from `artifacts/mobile/constants/brandMark.ts`, so it cannot drift from the app. Palette from `constants/colors.ts`:
  logo teal `#00A99D`, primary teal `#006D65`, midnight ink `#0B1B33`, paper `#F6F5F1`. Reel 2 sits on paper with an
  ink-and-teal end card; Reel 5 on deep teal with a white lockup. `reel_lib.py` carries the grounds as `THEMES`.
- Copy spells the name «اقرأ», as the brief and the wordmark do (Reels 6–9's first cut wrote «إقرأ»; their rebuild
  should fix that).

## What is real, what is staged (Reels 2–4)

Everything on screen is a real screen of this repo's app, recorded in a phone-sized browser against a
throwaway local Postgres. Nothing is sent to a real person: there is no email service, no push, and the
accounts exist only on that machine.

- **Accounts.** One fictional teacher «سلمى الخطيب» per reel, created through the real `/auth/register`
  route. `email_verified` is set directly in SQL because there is no mailer locally; the roster-consent
  prompt («أُقرّ بذلك») is acknowledged off-camera on that fictional account.
- **Reel 2.** Nothing staged. The library is the real المكتبة tab, and the search is the lesson already
  shown in the app's own lesson bar («تركيب الاقترانات»); the one result is what the library holds for it.
- **Reel 3.** The teacher starts with two seeded classes so the overview has cards. On camera: «شعبة جديدة»,
  the name typed, الكيمياء switched off, «أنشئ الشعبة», the add-students sheet (first names only, all
  fictional), back to the overview (now three classes), and the new class opened. Dead time is sped up.
- **Reel 4.** Class «الثامن علوم أ» with three student accounts and two parent accounts, all created through the
  real claim-code flow (`STUDENT_ACCOUNTS=true`, as in production). The class-group thread is created before any
  message; both messages are the demo texts from the brief and exist only in that local database. The pill
  «محادثة تجريبية · حساب تجريبي» says so on screen.
- **Wording.** The app calls a class a «شعبة»; the brief's copy says «صف / صفوف» and is kept verbatim, so Reel 3's
  headlines say «صفّك» over screens that say «شعبة».

## Reels 2 and 5 — re-recorded (sheet regenerated, new brand)

The premade «تركيب الاقترانات» sheet changed when its repeated questions were fixed (10 → 4 questions, now with a
worked example, a half-solved example and a key with working). Both reels were re-recorded against it —
`capture/r2n_record.cjs`, `capture/r5n_record.cjs` — and built by `build_rebrand_reels.py`; `capture/sheetnav.cjs`
finds headings by text so the walk does not depend on pixel offsets.

- **Reel 2** is a section-by-section tour of one sheet: library → search → open → «مثال محلول» → «مثال نكمله» →
  «أ) تمارين تمهيدية (سهل)» → «مفتاح الإجابات».
- **Reel 5** is a quiz show: item 1 (f(x) = x² − 1, find f(3)), a 3-2-1 ring, then the key's own three lines of working
  lit one at a time, then the library card.
- **Nothing says «verified».** Every key in the premade library is `verificationSource: 'bank'` (computed with its
  question) — none is `'symbolic'`. 3² − 1 = 8 was checked by hand; so were the inverse and composition rows.
- **Kept off screen, on the same sheet:** item 2 (an Arabic «و» reads as a "9" beside Latin maths, and 9 is its answer);
  key row 3, whose «(f∘g)(2) = f(g(2))» draws mirrored in the app; item 4 (`a_n = 3n − 1`, an arithmetic sequence on a
  function-composition sheet — off topic for the lesson, a gap in the offline bank).
- `verify_reel.py` now tells light grounds from dark ones: on a light ground «content in the margin» means anything
  clearly darker than paper, not anything bright.

## Reels 10–12 — features that exist today

Built after the library reel's «ورقة عمل» wording was challenged: the library itself only holds real, offline-safe content
for worksheets (24, Grade 10 maths); its infographic / image / audio / game / template / presentation shelves are empty
until someone uploads items, and its 4 videos and 11 book sources are external links to non-maths subjects. So these three
reels film features that run today, with nothing seeded or staged. `build_new_feature_reels.py`; takes
`capture/r10_record.cjs`, `r11_record.cjs`, `r12_record.cjs`.

- **10 «ألعاب إقرأ»** — the public hub (no sign-up) and the element-symbols game. Every tap is a correct answer, looked up
  in the game's own data (`services/publicGames/elements.ts`); 8 of 8. A segment ticker fills as the answers land.
  Flags / capitals need internet (`flagcdn.com`) and are not filmed.
- **11 «الحصة التفاعلية»** — Tools tab → the activity catalogue (one activity lit at a time) → the set-up form → «النشاط جاهز
  للعرض». Demo-mode content, so it carries the demo pill; the generated slides (maths text) are not shown.
- **12 «المنهاج»** — library card → الرياضيات → الفصل الثاني → الاقترانات → «تركيب الاقترانات», then the lesson page.
  The lesson page's «مكتبة الدرس» card names a real teacher who uploaded a file; it is blurred in the take and cropped out of
  every scene. The «نتاجات التعلّم» block (English «Understand» chips in an Arabic page) is also left out.
- Left out entirely: «ركن الإنجليزية» (Arabic glosses are AI-drafted and unreviewed; audio is silent offline) and «المختبر»
  (not yet verified in a browser; PhET is gated until a teacher reviews it).

## Rebuilding

```bash
# 1. the app (see ../../LOCAL_SETUP.md): Postgres up, .env with DATABASE_URL, SESSION_SECRET, OPENAI_API_KEY=dummy
#    and STUDENT_ACCOUNTS=true; then
pnpm --filter @workspace/db run migrate && pnpm --filter @workspace/db run seed:assessment
pnpm run dev:api                                              # :8080
(cd ../../artifacts/mobile && EXPO_PUBLIC_API_BASE_URL=http://localhost:8080/api CI=1 npx expo export --platform web)
node capture/serve.mjs ../../artifacts/mobile/dist &          # :8081, SPA fallback

# 2. fictional demo state + signed-in browser sessions (wipes the LOCAL users table, then re-seed assessment)
capture/prep_all.sh

# 3. record a take, then build  (relogin first: access tokens last 15 min and refresh tokens rotate)
node capture/r3_record.cjs                          # r3 / r4 sessions: node capture/relogin.cjs demo.classes@example.com r3
node capture/relogin.cjs demo.messages@example.com r4 && node capture/r4_record.cjs

node render_overlays.js && python3 make_music.py out/bed.wav 23.5
python3 build_reel1.py && python3 build_reel3.py && python3 build_reel4.py
node make_brand.mjs && node render_overlays.js
node capture/relogin.cjs demo.library@example.com r2 && node capture/r2n_record.cjs
node capture/relogin.cjs demo.library@example.com r2 && node capture/r5n_record.cjs && python3 build_rebrand_reels.py 2 5
python3 verify_reel.py out/Iqrra_02_Library.mp4              # format, loudness, black frames, safe-zone margins
```

Recording uses Chrome's screencast (`capture/rec.cjs`) at 2× so the footage is crisp and scrolling stays smooth
(3× dropped to ~19 fps). It logs every pointer move and tap; `reel_lib.py` draws the arrow and the tap ripple from
that log, so a highlight always sits where the click really landed. Cameras are written in CSS pixels of the
390×844 viewport. Playwright is loaded from `/opt/node-tools` — adjust the path in `capture/common.cjs` elsewhere.

`take`s are committed (`capture/takes/*.mp4` + `.events.json`) so the reels rebuild without re-recording.

## Music

Two original synthesised beds — no third-party licence. Neither of the five stock tracks used by the earlier reel is in
the repo, and `docs/marketing-plan.md` still lists "music licences" as unbought. To use a licensed track, replace the
bed (`out/bed.wav`) and rebuild.

- **Soft bed** — `make_music.py` (100 BPM ambient pad + plucks). Still on Reels 1, 3, 4, 6–9. Judged too flat.
- **Upbeat** — `music_upbeat.py` (118 BPM, four-on-the-floor kick, claps, bouncing bass that ducks under the kick, plucked
  stabs, a marimba hook, a sparkle arp from bar 5, a riser into the end card). **Default for new reels**: set
  `music="upbeat"` in the reel's config. It also follows the picture: a whoosh into every scene cut and a pop on it, plus
  `dings=[t, …]`, a rising-scale ding for each event (Reel 10: one per correct answer).
  **Reels 2, 5, 10, 11, 12 use it** (dings: Reel 5 on each countdown number, the reveal and each key line; Reel 10 on each
  correct answer; Reel 11 on each activity as it lights up). Re-music an older reel by adding `music="upbeat"` to its
  config and rebuilding.
- **Oriental** — `music_oriental.py` (98 BPM, tonic D, **Hijaz** scale: darbuka maqsum, riq 16ths, an oud-style question-and-answer
  melody with grace notes, a qanun octave from bar 5, a D + A string drone). Same interface, so `music="oriental"` in a reel's
  config; accents are a riq roll into each cut, a "tak" on it, qanun notes climbing Hijaz for `dings`, and a final D strum.
  Sample: `out/Iqrra_13_Poster_Sample_oriental.mp4` (`python3 build_poster_reel.py oriental`).
